Surface 与 Texture 的区别

SDL_Surface* sur_img = IMG_Load(...);
SDL_Texture* tex_img = SDL_CreateTextureFromSurface(renderer, sur_img);
  • Surface：存在内存（CPU 侧）的像素数据，可以读写像素，但不能直接渲染。
  • Texture：存在显存/GPU（驱动侧）的纹理，只能渲染不能读写（一般如此）。
  • 两者的桥梁就是 SDL_CreateTextureFromSurface。文件 → Surface → Texture 是 SDL 加载图片的标准流程。

解决mpu6050打印z轴数据出现0.000

出现 0.000 的根本原因核心原因：数值绝对值小于 0.0005（即半量化步长），被“+0.5 后取整”的舍入方式吞掉了。

原代码对加速度 Z 轴小数部分的提取逻辑是：

(int)(abs(corrected_data.accel_z_g * 1000 + 0.5) % 1000)
当实际物理值落在 [-0.0005, +0.0005) 这个区间时：

若 value = 0.0004：
0.0004 × 1000 + 0.5 = 0.9 → 取整为 0 → 打印 0.000

若 value = -0.0004：
-0.0004 × 1000 + 0.5 = 0.1 → 取整为 0 → 打印 0.000

虽然这是正常的“四舍五入到 0”，但在噪声或静态偏置下，数据会频繁显示 0.000，看起来像“死区”或“卡顿”，缺乏物理变化的连续性。

次要原因（加重问题）：原代码对负数的舍入方向错误（向零舍入而非远离零），导致 -0.0006 本应显示 -0.001，却因 +0.5 后变为 -0.1 取整为 0，进一步扩大了 0.000 的显示范围。
