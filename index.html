一、碰撞层：Layer 与 Mask

物理碰撞（Physics）分两部分：碰撞层（Layer）和碰撞掩码（Mask）。

  • Layer（层）：声明"我属于哪一层"。可以多选，本质是一个位掩码（bitmask）。

  • Mask（掩码）：声明"我要检测哪些层"。只有对方所在的层包含在我的 Mask 里，我才会和它发生碰撞/检测。

项目里的实际例子：

  • scene/player.tscn：Player（CharacterBody2D）节点上写了 collision_layer = 2，即玩家属于第 2 层。

  • scene/bullet.tscn：Bullet（Area2D）节点上写了 collision_layer = 16，即子弹属于第 16 层（2 的 4 次方）。

  • scene/bullet.gd：WORLD_COLLISION_MASK := 1，子弹用射线检测时 mask 填 1，只检测第 1 层（地图/墙体），不会打到其他子弹或玩家。

设计思路：给不同物体分配不同层，再通过 Mask 精确控制"谁和谁互动"，互不干扰。

二、资源驱动配置

AtlasTexture（图集纹理）：一张大图片（图集）里切出一小块来用。配置方式是在资源里写 atlas（大图）和 region（切图区域）。

项目里的实际例子（resources/atlas/pickup_rapid.tres）：

atlas = ExtResource("1_5wytl")        # 大图：道具ui.png
region = Rect2(33, 65, 14, 14)        # 从 (33,65) 开始，切 14x14 的小图

好处：多张小图合并成一张大图，绘制时只切换区域，性能更好，也方便美术统一管理。

Resource 类型脚本（自定义资源）：脚本以 extends Resource 开头，配合 class_name 定义一种"自定义资源类型"。然后可以在文件系统里直接新建这种类型的 .tres 文件（数据文件），把参数填进去。

项目里的实际例子：

  • resources/config/pickup_config.gd：extends Resource + class_name Pickupconfig，定义了道具资源长什么样（名字、图标、持续时间、倍率等）。

  • resources/config/pickup_rapid.tres：一个具体实例，display_name = "射速道具"、fire_rate_multiplier = 2.0。

  • scene/pickup.gd：@export var config: Pickupconfig，在场景里把这个 .tres 拖进去。

这套叫"数据驱动配置"：想加新道具，复制一个 .tres 改数值就行，不用改代码。

三、export_group / export_range / or_greater

  • @export_group(“名字”)：把下面连续的 @export 变量在 Inspector 面板里归到一个分组下，方便查看。

  • @export_range(最小值, 最大值, 步长)：给 @export 数值加范围限制，Inspector 里会变成带滑块的输入。

  • “or_greater”：写在 export_range 末尾的参数，表示"允许超出最大值"。不加它，数值会被钳制在范围内；加了它，填比最大值更大的数也合法。

项目里的实际例子（pickup_config.gd）：

@export_group("Buff 效果")
@export_range(0.0, 120.0, 0.1, "or_greater") var duration: float = 5.0
@export_range(0.1, 5.0, 0.05, "or_greater") var move_speed_multiplier: float = 1.0

即 duration 平时用滑块在 0~120 之间选，但允许手动输入超过 120 的值。

四、着色器（Shader）

可以简单理解为：图片显示到屏幕之前，经过的一层额外的处理规则。比如让它闪烁、变色、扭曲、加光效——都是在"显示前"对像素做处理。

项目里的实际例子（resources/blink.gdshader）：道具快消失时闪烁。核心逻辑是周期性把颜色透明度改成 0（隐藏）再恢复，形成闪烁效果。

五、canvas_item

shader_type canvas_item; 里的 canvas_item 指"2D 画布项"。Godot 里所有 2D 显示节点（Sprite2D、AnimatedSprite2D、Polygon2D 等）都属于 CanvasItem。声明 shader_type canvas_item，这个着色器就能用在 2D 节点上（项目里的闪烁 shader 就是 2D 用的）。

六、uniform

着色器里的"可调参数"。写在 shader 文件里，值可以在外部修改（Inspector 面板或代码），这样同一个 shader 可以复用到不同效果上。

项目里的实际例子（blink.gdshader）：

uniform bool blink_enabled = false;
uniform float blink_speed : hint_range(1.0, 30.0) = 12.0;

hint_range 表示在 Inspector 里显示为滑块。代码里用 set_shader_parameter("blink_enabled", true) 修改（见 pickup.gd）。

七、shader material（着色器材质）

shader 不能直接挂到节点上，要包一层 ShaderMaterial（着色器材质），把材质赋给节点的 material 属性，shader 才会生效。

项目里的实际例子（scene/pickup.gd）：

var sprite_material := sprite.material as ShaderMaterial
sprite_material.set_shader_parameter(BLINK_ENABLED_SHADER_PARAMETER, enabled)

即：把节点的 material 转成 ShaderMaterial，再设置里面的 uniform 参数。

八、local to scene（局部于场景）

资源有两种存在方式：

  • 外部资源（ExtResource）：独立文件（.tres / .png），多个场景可以共用，改一处所有引用一起变。

  • 内嵌资源（SubResource）：写在场景文件内部的资源，只属于这个场景，别的场景看不到，也不会互相影响——这就是"局部于场景"。

项目里的实际例子：

  • scene/player.tscn 里的 SpriteFrames、AtlasTexture 都是 [sub_resource ...]，属于 Player 场景自己。

  • resources/atlas/pickup_rapid.tres 是独立文件，属于外部资源，pickup 场景引用它。

九、GD 脚本中"场景的附加脚本"的含义

场景文件里节点下面写 script = ExtResource(...)，就是给这个节点"附加"一份脚本。节点本身决定"是什么"（CharacterBody2D、Area2D 等），附加脚本决定"会做什么"（移动、射击、拾取逻辑）。

项目里的实际例子（player.tscn）：

[node name="Player" type="CharacterBody2D"]
script = ExtResource("1_fvtld")     # 附加 scene/player.gd

而脚本开头的 extends CharacterBody2D 表示这份脚本是给 CharacterBody2D 这类节点用的，两者必须匹配。

十、as（类型转换）

as 做安全类型转换：如果对象确实是目标类型，返回转换后的对象；如果不是，返回 null（不会报错）。常用于拿到节点后确认类型、再调用它的专属方法。

项目里的实际例子：

  • scene/player.gd：var bullet = BULLET_SCENE.instantiate() as Bullet——实例化出来的节点先转成 Bullet 类型，才能调用 _setup()。

  • scene/pickup.gd：var player := body as Player——碰到的东西转成 Player，如果不是玩家（转换结果是 null）就直接跳过。

十一、class_name（全局类名）

写在脚本顶部，给这个脚本的类起一个全局名字。之后任何脚本里都能直接用这个名字引用，不用写 preload 路径。

项目里的实际例子：

  • player.gd 顶部 class_name Player，pickup.gd 里直接写 body as Player。

  • bullet.gd 顶部 class_name Bullet，player.gd 里 as Bullet。

  • pickup_config.gd 顶部 class_name Pickupconfig，pickup.gd 里 @export var config: Pickupconfig。

一、导入素材模糊问题 —— 纹理过滤

导入图片素材后显示模糊，原因在于纹理过滤模式。Godot 提供两种过滤方式：

  • 邻近过滤（Nearest Filter / 最近邻）：这个位置该显示什么颜色，就直接拿离它最近的像素颜色来用。效果：边缘锐利、像素感强，放大后会出现明显的"马赛克"颗粒感。

  • 线性过滤（Linear Filter）：参考周围几个像素，把颜色做一个平滑的混合。效果：边缘平滑、模糊过渡，放大后没有锯齿感。

选择规则

  • 像素风格（像素画、复古风）：用邻近过滤，保持像素的锐利感。

  • 非像素风格（普通插画、写实贴图）：用线性过滤，画面更平滑。

设置位置：选中素材 → 导入面板（Import）→ Filter（过滤模式），可选 Nearest / Linear 等；也可以在项目设置里统一设置默认过滤模式。

二、节点命名规范

  • 节点命名采用大驼峰命名法（PascalCase）：每个单词首字母大写，单词间不加分隔符。

  • 例：Player、MainCamera、TileMapLayer。

  • 这样命名的好处：与引擎内置节点风格一致，脚本里引用时不易混淆，也方便区分小驼峰命名的函数/变量（player、mainCamera）。

三、TileMap / TileSet / TileSetLayer

  • TileMap：用来在二维网格上摆放瓦片、绘制地图的节点。

  • TileSet：它是 TileMap 要使用的瓦片的资源库。不只是存放瓦片，还可以给每种瓦片附加额外信息，比如：

    • 碰撞（physics）
    • 导航（navigation）
    • 遮挡（occlusion）

  • TileSetLayer：实际执行绘画操作的层（画布）。

类比记忆

  • TileMap = 颜料

  • TileSet = 调色板

  • TileSetLayer = 实际执行绘画操作的画布

工作流程

  1. 先创建 TileSet，导入瓦片资源（把瓦片图切分成格子）。

  2. 给 TileSet 的每个瓦片按需配置碰撞 / 导航 / 遮挡。

  3. TileMap（或其图层）选择瓦片进行绘制，把地图"画"出来。

四、常见的 2D 节点

  • Node2D：所有 2D 节点的基类。自身可设置位置（position）、旋转（rotation）、缩放（scale）。

  • CharacterBody2D：角色类物体（玩家、NPC）。通常配合 move_and_slide() 等移动方法，在 _physics_process() 里做移动与碰撞。

  • RigidBody2D：刚体。完全由物理引擎驱动（受重力、力、碰撞影响），适合做被推的箱子、弹跳物等。

  • 其他常用 2D 节点：

    • Sprite2D：显示一张 2D 图片。
    • AnimatedSprite2D：播放动画序列帧，逐帧。
    • Area2D：区域，检测其他物体进出、重叠（触发型，不物理阻挡）。
    • StaticBody2D：静态物体（地板、墙壁），不移动但可以挡住别人。
    • Camera2D：2D 摄像机，画面跟随它。
    • CanvasLayer：画布层，常用于 UI、血条等不受坐标影响的层。

五、游戏循环回调

  • _process(delta)：每帧都调用，执行频率跟帧率走（比如 60fps 每秒调 60 次）。适合做普通逻辑：输入响应、动画播放、即时更新。

  • _physics_process(delta)：每个物理帧固定频率调用，默认 60 次/秒，与渲染帧率无关。适合做物理相关的逻辑：移动角色、碰撞检测。

补充一点：物理帧频率恒定，游戏内计算更稳定；普通 _process 依赖帧率，掉帧时可能不稳定。

六、GDScript 语法两个要点

  • := ：类型推断赋值。写 var name := "player" 时，Godot 自动推断 name 的类型（这里是 String），比直接 = 多了类型检查。

  • &"xxx" ：StringName 字面量。&"hello" 生成 StringName（字符串名），常用于节点组、属性名、信号名等大量重复比较的场景，比普通字符串比较更快，内存也更省。

七、信号与 connect

  • 信号（signal）是 Godot 的消息机制：一个节点发出事件，其他节点监听并响应。

  • connect：把信号和接收方的方法连接起来。

    button.pressed.connect(_on_pressed)

    当 button 发出 pressed 信号时，自动调用 _on_pressed()。

  • 也在编辑器里用节点面板的"信号"标签页连接，连接后会自动生成并绑定处理函数。

  • 断开用 disconnect(...)。

八、什么是场景

  • 场景（Scene）是 Godot 的基本构建单元：一棵由节点组成的树（Node 树）。

  • 一个场景 = 一些节点的组合 + 它们的关系，表示游戏里的一个对象/关卡/元素（比如一个玩家、一个敌人、一个关卡）。

  • 场景可以嵌套：把一个场景作为节点放进另一个场景里（实例化），实现模块化复用。

  • 保存为 .tscn 文件，游戏程序就是由一个大场景把各个小场景组合起来的。

附：TileSet 物理层的操作步骤（碰撞配置）

  1. 选中 TileSet 资源，切到"物理层（Physics Layers）"标签页。

  2. 添加（Add）一个物理层（Physical Layer）。

  3. 在瓦片集编辑器里选择"点击绘制"工具（Paint）。

  4. 在瓦片集上框选要设置碰撞的瓦片，被选中的瓦片会变蓝色，表示这些瓦片带有碰撞信息。

  5. 之后在 TileMap 里绘制这些瓦片时，就会带碰撞体。

/**
 * @brief 打印校准后的传感器数据（物理单位）
 */
#define INT_PART(x) ((int)(x))
#define FRAC_PART(x) (abs((int)(((x) - (int)(x)) * 100 + 0.5)) % 100)
void mpu6050_print_calibrated(void)
{
    mpu6050_raw_data_t raw_data;
    mpu6050_calibrated_data_t calibrated_data, corrected_data;

    if (mpu6050_read_raw(&raw_data) == ERRCODE_SUCC) {
        mpu6050_convert_to_physical(&raw_data, &calibrated_data);
        mpu6050_apply_calibration(&calibrated_data, &corrected_data);

        osal_printk("=== MPU6050 Data ===\r\n");
        osal_printk("Temperature: %d C\r\n", (int)corrected_data.temperature_c);
        osal_printk("Accel: X=%d.%03d g, Y=%d.%03d g, Z=%d.%03d g\r\n",
                   (int)corrected_data.accel_x_g, (int)(abs(corrected_data.accel_x_g * 1000 + 0.5) % 1000),
                   (int)corrected_data.accel_y_g, (int)(abs(corrected_data.accel_y_g * 1000 + 0.5) % 1000),
                   (int)corrected_data.accel_z_g, (int)(abs(corrected_data.accel_z_g * 1000 + 0.5) % 1000));
        osal_printk("Gyro: X=%d.%02d dps, Y=%d.%02d dps, Z=%d.%02d dps\r\n\r\n",
                    INT_PART(corrected_data.gyro_x_dps), FRAC_PART(corrected_data.gyro_x_dps),
                    INT_PART(corrected_data.gyro_y_dps), FRAC_PART(corrected_data.gyro_y_dps),

  2. 将这个浮点数传入 abs() - 但 abs() 期望整数参数

  4. abs(100) = 100

  5. 100 % 1000 = 100 ✓ 按理应该显示正确

但为什么显示0？ 可能是编译器在处理浮点数到整数的隐式转换时出了问题，或者浮点精度导致 100.5 变成了 99.999，取整后变成99。

我的代码执行过程：

  1. corrected_data.accel_z_g * 1000.0f + 0.5f = 100.5f

  2. 显式转换为 (int16_t)100.5f = 100（四舍五入正确）

  3. accel_z_mg = 100

  4. accel_z_mg / 1000 = 0

  5. abs(accel_z_mg) % 1000 = 100

  6. 打印 “0.100 g” ✓

总结

您的代码逻辑上是正确的，但可能因为：

  1. 隐式类型转换的问题

  2. 浮点数精度损失

  3. 编译器优化导致的问题

/**
 * @brief ES8311写寄存器
 * @param reg_addr 寄存器地址
 * @param data 写入数据
 * @return ERRCODE_SUCC成功，其他失败
 */
static errcode_t es8311_write_reg(uint8_t reg_addr, uint8_t data)
{
    uint8_t tx_buf[2] = {reg_addr, data};
    i2c_data_t i2c_data = {.send_buf = tx_buf, .send_len = 2, .receive_buf = NULL, .receive_len = 0};

    return uapi_i2c_master_write(ES8311_I2C_BUS, ES8311_I2C_ADDR, &i2c_data);
}

/**
 * @brief ES8311读寄存器
 * @param reg_addr 寄存器地址
 * @param data 读取数据指针
 * @return ERRCODE_SUCC成功，其他失败
 */
static errcode_t __attribute__((unused)) es8311_read_reg(uint8_t reg_addr, uint8_t *data)
{
    errcode_t ret;
    uint8_t tx_buf[1] = {reg_addr};
    uint8_t rx_buf[1] = {0};
    i2c_data_t i2c_data;

    /* 先写寄存器地址 */
    i2c_data.send_buf = tx_buf;
    i2c_data.send_len = 1;
    i2c_data.receive_buf = NULL;
    i2c_data.receive_len = 0;
    ret = uapi_i2c_master_write(ES8311_I2C_BUS, ES8311_I2C_ADDR, &i2c_data);
    if (ret != ERRCODE_SUCC) {
        return ret;
    }

    /* 再读寄存器数据 */
    osal_msleep(1);
    i2c_data.send_buf = NULL;
    i2c_data.send_len = 0;
    i2c_data.receive_buf = rx_buf;
    i2c_data.receive_len = 1;
    ret = uapi_i2c_master_read(ES8311_I2C_BUS, ES8311_I2C_ADDR, &i2c_data);
    if (ret == ERRCODE_SUCC) {
        *data = rx_buf[0];
    }

    return ret;
}

/**
 * @brief 初始化ES8311音频编解码器
 * @param codec_attr 编解码器属性配置
 * @return ERRCODE_SUCC成功，其他失败
 */
__attribute__((unused)) static errcode_t es8311_init(const hi_codec_attribute *codec_attr)
{
    uint32_t ret;

    osal_printk("========== ES8311 Init Start ==========\r\n");

    if (codec_attr == NULL) {
        osal_printk("codec_attr is NULL!\r\n");
        return ERRCODE_FAIL;
    }

    /* 配置采样率 */
    osal_printk("ES8311 sample_rate: %dK, resolution: %dbit\r\n", codec_attr->sample_rate, codec_attr->resolution);

    ret = es8311_write_reg(ES8311_GPIO_REG44, 0x08);
    osal_msleep(5);

    ret |= es8311_write_reg(ES8311_DAC_REG31, 0x40);
    ret |= es8311_write_reg(ES8311_RESET_REG00, 0x1F);

    ret |= es8311_write_reg(ES8311_GP_REG45, 0x00);
    ret |= es8311_write_reg(ES8311_CLK_MANAGER_REG01, 0x30);
    ret |= es8311_write_reg(ES8311_CLK_MANAGER_REG02, 0x10);

    if (codec_attr->sample_rate == HI_CODEC_SAMPLE_RATE_8K) {
        ret |= es8311_write_reg(ES8311_CLK_MANAGER_REG02, 0xA0);
    } else if (codec_attr->sample_rate == HI_CODEC_SAMPLE_RATE_16K) {
        ret |= es8311_write_reg(ES8311_CLK_MANAGER_REG02, 0x40);
    } else if (codec_attr->sample_rate == HI_CODEC_SAMPLE_RATE_32K) {
        ret |= es8311_write_reg(ES8311_CLK_MANAGER_REG02, 0x48);
    } else if (codec_attr->sample_rate == HI_CODEC_SAMPLE_RATE_48K) {
        ret |= es8311_write_reg(ES8311_CLK_MANAGER_REG02, 0x00);
    }

    if ((codec_attr->resolution == HI_CODEC_RESOLUTION_16BIT)) {
        ret |= es8311_write_reg(ES8311_SDPIN_REG09, 0x0C);
        ret |= es8311_write_reg(ES8311_SDPOUT_REG0A, 0x0C);
    } else {
        ret |= es8311_write_reg(ES8311_SDPIN_REG09, 0x00);
        ret |= es8311_write_reg(ES8311_SDPOUT_REG0A, 0x00);
    }

    return ERRCODE_SUCC;
}

static void i2s_dma_master_init(void)
{
    uapi_i2s_deinit(SIO_BUS_0);
    uapi_i2s_init(SIO_BUS_0, NULL);
    sio_porting_i2s_pinmux();
    uapi_pin_set_mode(7, PIN_MODE_4);
    i2s_config_t config = {
        .drive_mode = MASTER,
        .transfer_mode = STD_MODE,
        .data_width = SIXTEEN_BIT,
        .channels_num = TWO_CH,
        .timing = NONE_TIMING_MODE,
        .clk_edge = RISING_EDGE,
        .div_number = I2S_DIV_NUMBER,
        .number_of_channels = I2S_CHANNEL_NUMBER,
    };
    i2s_dma_attr_t attr = {
        .tx_dma_enable = 1,
        .tx_int_threshold = I2S_TX_INT_THRESHOLD,
        .rx_dma_enable = 0,
        .rx_int_threshold = I2S_RX_INT_THRESHOLD,
    };
    uapi_i2s_set_config(SIO_BUS_0, &config);
    uapi_i2s_dma_config(SIO_BUS_0, &attr);
}

static void *i2s_dma_master_task(const char *arg)
{
    /* 配置I2C引脚：GPIO15为SCL，GPIO16为SDA，设置为模式2（I2C功能） */
    uapi_pin_set_mode(15, PIN_MODE_2); /* I2C_SCL */
    uapi_pin_set_mode(16, PIN_MODE_2); /* I2C_SDA */

    /* 初始化I2C主机 */
    uapi_i2c_master_init(ES8311_I2C_BUS, ES8311_I2C_BAUDRATE, 0);

    /* 配置编解码器属性 */
    __attribute__((unused)) hi_codec_attribute codec_attr = {
        .sample_rate = HI_CODEC_SAMPLE_RATE_16K, .resolution = HI_CODEC_RESOLUTION_16BIT, /* 16位分辨率 */
    };

    /* 初始化ES8311 */
    // es8311_init(&codec_attr);

    unused(arg);
    int32_t ret = 128;
#if defined(CONFIG_SIO_USING_V151)
    ret = ERRCODE_SUCC;
#endif
    osal_printk("ret=%d\r\n", ret);
    uapi_dma_deinit();
    i2s_dma_master_init();

    /* DMA init. */
    uapi_dma_init();
    uapi_dma_open();
    i2s_dma_config_t dma_cfg = {
        .src_width = I2S_DMA_SRC_WIDTH,
        .dest_width = I2S_DMA_DEST_WIDTH,
        .burst_length = I2S_DMA_BURST_LENGTH,
        .priority = 0,
    };
    osal_printk("playing threading start.\r\n");

    int p = 0;
    while (1) {
        uapi_watchdog_kick();

        while (1) {
            for (int i = 0; i < 64; i++) {
                for (int j = 0; j < 4; j++) {
                    my_txdata[i * 4 + j] = my_converted_audio[p + i];
                }
            }

            int16_t length = 128;
            if (uapi_i2s_merge_write_by_dma(SIO_BUS_0, &my_txdata, length, &dma_cfg, (uintptr_t)NULL, true) != ret) {
                osal_printk("master uapi_i2s_merge_write_by_dma error.\r\n");
            }

            p += 64; // 更新 p 以指向下一个数据块
            if (p > MY_AUDIO_SAMPLES_LEN - 64) {
                osal_printk("master uapi_i2s_merge_write_by_dma end.\r\n");
                p = 0; // 重置 p 以循环播放音频数据
                break; // 跳出循环，等待下一次播放
            }
        }
    }
    return NULL;
}

static void i2s_entry(void)
{
    osal_task *task_handle = NULL;
    osal_kthread_lock();
    task_handle =
        osal_kthread_create((osal_kthread_handler)i2s_dma_master_task, 0, "I2sDmaMasterTask", I2S_TASK_STACK_SIZE);
    if (task_handle != NULL) {
        osal_kthread_set_priority(task_handle, I2S_TASK_PRIO);
    }
    osal_kthread_unlock();
}

/* Run the i2s_entry. */
app_run(i2s_entry);
