Godot课程笔记--从零开始的Godot游戏开发002

2026/8/12 学习 Godot, 学习日记

一、碰撞层：Layer 与 Mask

物理碰撞（Physics）分两部分：碰撞层（Layer）和碰撞掩码（Mask）。

  • Layer（层）：声明"我属于哪一层"。可以多选，本质是一个位掩码（bitmask）。

  • Mask（掩码）：声明"我要检测哪些层"。只有对方所在的层包含在我的 Mask 里，我才会和它发生碰撞/检测。

项目里的实际例子：

  • scene/player.tscn：Player（CharacterBody2D）节点上写了 collision_layer = 2，即玩家属于第 2 层。

  • scene/bullet.tscn：Bullet（Area2D）节点上写了 collision_layer = 16，即子弹属于第 16 层（2 的 4 次方）。

  • scene/bullet.gd：WORLD_COLLISION_MASK := 1，子弹用射线检测时 mask 填 1，只检测第 1 层（地图/墙体），不会打到其他子弹或玩家。

设计思路：给不同物体分配不同层，再通过 Mask 精确控制"谁和谁互动"，互不干扰。

二、资源驱动配置

AtlasTexture（图集纹理）：一张大图片（图集）里切出一小块来用。配置方式是在资源里写 atlas（大图）和 region（切图区域）。

项目里的实际例子（resources/atlas/pickup_rapid.tres）：

atlas = ExtResource("1_5wytl")        # 大图：道具ui.png
region = Rect2(33, 65, 14, 14)        # 从 (33,65) 开始，切 14x14 的小图

好处：多张小图合并成一张大图，绘制时只切换区域，性能更好，也方便美术统一管理。

Resource 类型脚本（自定义资源）：脚本以 extends Resource 开头，配合 class_name 定义一种"自定义资源类型"。然后可以在文件系统里直接新建这种类型的 .tres 文件（数据文件），把参数填进去。

项目里的实际例子：

  • resources/config/pickup_config.gd：extends Resource + class_name Pickupconfig，定义了道具资源长什么样（名字、图标、持续时间、倍率等）。

  • resources/config/pickup_rapid.tres：一个具体实例，display_name = "射速道具"、fire_rate_multiplier = 2.0。

  • scene/pickup.gd：@export var config: Pickupconfig，在场景里把这个 .tres 拖进去。

这套叫"数据驱动配置"：想加新道具，复制一个 .tres 改数值就行，不用改代码。

三、export_group / export_range / or_greater

  • @export_group(“名字”)：把下面连续的 @export 变量在 Inspector 面板里归到一个分组下，方便查看。

  • @export_range(最小值, 最大值, 步长)：给 @export 数值加范围限制，Inspector 里会变成带滑块的输入。

  • “or_greater”：写在 export_range 末尾的参数，表示"允许超出最大值"。不加它，数值会被钳制在范围内；加了它，填比最大值更大的数也合法。

项目里的实际例子（pickup_config.gd）：

@export_group("Buff 效果")
@export_range(0.0, 120.0, 0.1, "or_greater") var duration: float = 5.0
@export_range(0.1, 5.0, 0.05, "or_greater") var move_speed_multiplier: float = 1.0

即 duration 平时用滑块在 0~120 之间选，但允许手动输入超过 120 的值。

四、着色器（Shader）

可以简单理解为：图片显示到屏幕之前，经过的一层额外的处理规则。比如让它闪烁、变色、扭曲、加光效——都是在"显示前"对像素做处理。

项目里的实际例子（resources/blink.gdshader）：道具快消失时闪烁。核心逻辑是周期性把颜色透明度改成 0（隐藏）再恢复，形成闪烁效果。

五、canvas_item

shader_type canvas_item; 里的 canvas_item 指"2D 画布项"。Godot 里所有 2D 显示节点（Sprite2D、AnimatedSprite2D、Polygon2D 等）都属于 CanvasItem。声明 shader_type canvas_item，这个着色器就能用在 2D 节点上（项目里的闪烁 shader 就是 2D 用的）。

六、uniform

着色器里的"可调参数"。写在 shader 文件里，值可以在外部修改（Inspector 面板或代码），这样同一个 shader 可以复用到不同效果上。

项目里的实际例子（blink.gdshader）：

uniform bool blink_enabled = false;
uniform float blink_speed : hint_range(1.0, 30.0) = 12.0;

hint_range 表示在 Inspector 里显示为滑块。代码里用 set_shader_parameter("blink_enabled", true) 修改（见 pickup.gd）。

七、shader material（着色器材质）

shader 不能直接挂到节点上，要包一层 ShaderMaterial（着色器材质），把材质赋给节点的 material 属性，shader 才会生效。

项目里的实际例子（scene/pickup.gd）：

var sprite_material := sprite.material as ShaderMaterial
sprite_material.set_shader_parameter(BLINK_ENABLED_SHADER_PARAMETER, enabled)

即：把节点的 material 转成 ShaderMaterial，再设置里面的 uniform 参数。

八、local to scene（局部于场景）

资源有两种存在方式：

  • 外部资源（ExtResource）：独立文件（.tres / .png），多个场景可以共用，改一处所有引用一起变。

  • 内嵌资源（SubResource）：写在场景文件内部的资源，只属于这个场景，别的场景看不到，也不会互相影响——这就是"局部于场景"。

项目里的实际例子：

  • scene/player.tscn 里的 SpriteFrames、AtlasTexture 都是 [sub_resource ...]，属于 Player 场景自己。

  • resources/atlas/pickup_rapid.tres 是独立文件，属于外部资源，pickup 场景引用它。

九、GD 脚本中"场景的附加脚本"的含义

场景文件里节点下面写 script = ExtResource(...)，就是给这个节点"附加"一份脚本。节点本身决定"是什么"（CharacterBody2D、Area2D 等），附加脚本决定"会做什么"（移动、射击、拾取逻辑）。

项目里的实际例子（player.tscn）：

[node name="Player" type="CharacterBody2D"]
script = ExtResource("1_fvtld")     # 附加 scene/player.gd

而脚本开头的 extends CharacterBody2D 表示这份脚本是给 CharacterBody2D 这类节点用的，两者必须匹配。

十、as（类型转换）

as 做安全类型转换：如果对象确实是目标类型，返回转换后的对象；如果不是，返回 null（不会报错）。常用于拿到节点后确认类型、再调用它的专属方法。

项目里的实际例子：

  • scene/player.gd：var bullet = BULLET_SCENE.instantiate() as Bullet——实例化出来的节点先转成 Bullet 类型，才能调用 _setup()。

  • scene/pickup.gd：var player := body as Player——碰到的东西转成 Player，如果不是玩家（转换结果是 null）就直接跳过。

十一、class_name（全局类名）

写在脚本顶部，给这个脚本的类起一个全局名字。之后任何脚本里都能直接用这个名字引用，不用写 preload 路径。

项目里的实际例子：

  • player.gd 顶部 class_name Player，pickup.gd 里直接写 body as Player。

  • bullet.gd 顶部 class_name Bullet，player.gd 里 as Bullet。

  • pickup_config.gd 顶部 class_name Pickupconfig，pickup.gd 里 @export var config: Pickupconfig。
